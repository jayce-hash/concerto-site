# Social preview fix — what changed

Every page on the site now carries one complete, consistent Open Graph +
Twitter Card block pointing at a single 1200x630 card:
`https://concertocity.com/ConcertoSocialPreview.png`.

## What was broken
- 86 pages (all 77 tour pages + 9 others) pointed og:image at `og-image.jpg`,
  which does not exist in the repo. A 404 image makes Facebook, Instagram,
  iMessage, etc. drop it and grab a random on-page image, then crop it. That
  is the garbled "NCER / THE CONCERT TO TH" card.
- 362 pages (all 346 venue pages, partners.html, and ~15 others) had no
  og:image at all. Same fallback-and-crop behavior.
- The few working pages were split across two different image files.

## What each page has now
og:type, og:url, og:title, og:description, og:image (+ secure_url, type,
width=1200, height=630, alt), og:site_name, twitter:card=summary_large_image,
twitter:url, twitter:title, twitter:description, twitter:image, twitter:image:alt.

Titles and descriptions were preserved from each page's existing values
(og:* if present, otherwise the <title> and meta description).

## IMPORTANT: build pipeline
If venue/tour/index pages are regenerated by your build script from templates,
these direct edits get overwritten on the next deploy. To make the fix
permanent, add this block to the <head> of your page template(s), and drop the
old `og-image.jpg` reference. Use the page's own title/description/url:

  <meta property="og:type" content="website" />
  <meta property="og:url" content="{{page_url}}" />
  <meta property="og:title" content="{{title}}" />
  <meta property="og:description" content="{{description}}" />
  <meta property="og:image" content="https://concertocity.com/ConcertoSocialPreview.png" />
  <meta property="og:image:secure_url" content="https://concertocity.com/ConcertoSocialPreview.png" />
  <meta property="og:image:type" content="image/png" />
  <meta property="og:image:width" content="1200" />
  <meta property="og:image:height" content="630" />
  <meta property="og:image:alt" content="Concerto, from the concert to the city" />
  <meta property="og:site_name" content="Concerto" />
  <meta name="twitter:card" content="summary_large_image" />
  <meta name="twitter:url" content="{{page_url}}" />
  <meta name="twitter:title" content="{{title}}" />
  <meta name="twitter:description" content="{{description}}" />
  <meta name="twitter:image" content="https://concertocity.com/ConcertoSocialPreview.png" />
  <meta name="twitter:image:alt" content="Concerto, from the concert to the city" />

## After deploying
Re-scrape so the platforms drop their cached (broken) version:
- Facebook / Instagram: developers.facebook.com/tools/debug -> paste URL -> Scrape Again
- Twitter/X: cards-dev.twitter.com/validator
- iMessage/Slack/Discord cache by URL; a fresh URL or a re-share picks up the new card.
